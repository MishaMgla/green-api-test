# Стиль кода

Читать перед тем, как писать код.

## Принципы

1. **Не писать, если можно не писать.** Спекулятивная функциональность не пишется.
   Требования нет в ТЗ — кода нет.
2. **Сначала посмотреть, что уже есть.** Хелпер, тип, паттерн в соседнем файле —
   переиспользуем. Дублирование того, что лежит в двух файлах отсюда, — самая
   частая ошибка.
3. **Стандартная библиотека и платформа вперёд зависимостей.** `fetch` вместо
   axios, `<input type="date">` вместо пикера, CSS вместо JS.
4. **Новая зависимость — только если своими силами это десятки строк.**
5. Скучное лучше умного. Умное — это то, что разбирают в 3 часа ночи.

## Практика

- TypeScript strict. `any` — только на границе с нетипизированным JSON извне,
  и сразу сужаем до своего типа.
- Функции без побочных эффектов (парсинг, нормализация) выносим отдельно —
  их легко проверить без браузера.
- Валидация ввода и обработка ошибок не упрощаются никогда. Ошибка сети должна
  быть видна пользователю текстом, а не проглочена в консоль.
- Комментарий объясняет «почему», а не «что». Сознательное упрощение помечаем
  комментарием с потолком и путём апгрейда.
- Имена на английском, тексты интерфейса — на языке задания.

## Проверки

Нетривиальная логика (ветвление, парсер, разбор ответа API) оставляет после себя
один запускаемый тест — минимальный, без фреймворков:

```
node --test src/*.test.ts     # Node 24 исполняет TS напрямую
```

Тривиальные однострочники не тестируем.
